# Changelog — Claude Deck

Version lives in `com.claudedeck.deck.plugin.ulanziPlugin/manifest.json` (`Version`).
Rule: every user-visible change bumps the version here **and** in the manifest
(patch = fix/tweak, minor = new action/feature, major = breaking/UUID-level).
Store zips are built from this version.

## 2.4.0 — 2026-09-16

Answers [#4](https://github.com/chilleno/claude-deck/issues/4) (Ulanzi Studio team): lower the barrier to entry.

- **Setup checklist in every panel** — Studio gives a plugin no onboarding surface, so a key that does nothing looked the same whether Claude Code was missing, the hooks were never wired, or macOS was blocking terminal control. The panels now show those as five rows with a status dot and the reason (Claude Code · Claude tracking · Terminal control · Big screen · Sessions), one actionable hint underneath, and a button per fixable row. Polls every 3 s so nothing looks stale after a fix (`property-inspector/pi-setup.js`, replaces `pi-hooks.js`)
- **Bundled user guide, 9 languages** — "User Guide" button in all three panels opens `property-inspector/guide/<lang>.html` in the browser (`tools/build-guide.py`). Bundled rather than hosted: it works offline and always matches the installed version. Action names and tooltips are read back from the language files, so the guide can't drift from what Studio lists. Each page carries a language switcher (relative links between the sibling pages, current one marked `aria-current`), with every language written in its own script — a reader who landed on the wrong page can still find theirs
- **The hook no longer needs python3** — `hooks/claude-hook.js` is a Node port of `claude-hook.py`, registered with `process.execPath`: the plugin already runs on the Node that Ulanzi Studio ships, so that's an absolute path guaranteed to exist. On a clean consumer Mac `/usr/bin/python3` is only a stub that opens the Xcode Command Line Tools installer — the hooks would silently never run and every key would sit grey with no explanation. python3 stays as the fallback when `execPath` can't be resolved. Verified byte-identical to the python hook across 19 event cases (every state mapping, both ordering protections, the ask payloads, the info block, tty carry-over, malformed stdin)
- **Existing installs are upgraded, not duplicated** — re-running the setup rewrites any hook entry of ours that carries an old command line, collapses duplicates, and leaves other tools' hooks untouched; the panel reports `outdated` so it can offer an update instead of nagging about a missing setup
- **Detection no longer misses a working install** — a `~/.claude*` directory without `settings.json`, a `~/.claude.json` with no profile directory, or just the `claude` binary on the login shell's PATH all now count as installed, and the setup creates the missing `settings.json` (with its directory). Previously any of those reported "no Claude Code installation found" and hid the only button that could fix it
- **"Not set up" no longer looks like "no session"** — keys with nothing tracked show their own art in black and white (2.3.0); when the setup itself is incomplete they now carry an amber badge instead, the big key shows a "setup needed" screen naming what's missing, and the press toast points at the panel (`resources/setup/`, `renderSetupNeeded()`)
- **Terminal access can be checked on purpose** — a button in the panel raises the macOS Automation prompt and reports allowed / blocked, instead of leaving it to be discovered when a key silently fails (`checkTerminalAccess()` in `plugin/terminals.js`)
- Panel strings are now generated from one table for all 9 languages (`tools/build-locales.py`), with `tools/check-locales.py` as a gate: 45 strings, no missing keys, no dead keys, `{n}` placeholders preserved
- Store zip rebuilt from the installed plugin folder

## 2.3.0 — 2026-09-16

Fixes the three points reported by the Ulanzi Studio team in [#3](https://github.com/chilleno/claude-deck/issues/3).

- **Keys keep their own artwork when no session is tracked** — every key used to swap to the shared `fail.png` the moment `readStates()` came back empty, so a freshly installed deck showed six identical dead-face keys that matched nothing in Studio's action list (that mismatch was the report). Each key now shows *its own* icon in black and white instead (`resources/offline/`, generated by `tools/make-offline-icons.py`: greyscale at 72 % luminance, alpha kept, 196×196), and returns to colour as soon as a session is detected. Affects Pet, Option Next, Option OK, Session Switch, Compact and Clear
- **The greyscale is explained in four places**, since Studio gives a plugin nowhere to document itself: a legend at the foot of every property-inspector panel (translated), a sentence appended to the six action tooltips (translated), a `grey keys = nothing detected` line on the big key's "no session" screen, and a shared toast on any press with nothing tracked (`NO_SESSION_TOAST`)
- **Property inspectors are translated** — the SDK's `localizeUI()` only rewrites `[data-localize]` elements from the language file's `Localization` map; every panel string was hardcoded English and all nine `Localization` maps were empty, so panels stayed English even with Studio in Chinese. 21 strings now localized across all 9 languages, including the script-written hook-status line (`$UD.t()` in `pi-hooks.js`, re-rendered once the language file resolves — it deliberately carries no `data-localize`, or the SDK's one-shot pass would overwrite a rendered status with "Checking…")
- **Fix: the "Enable Claude tracking" button clipped its own label** — `libs/css/uspi.css` pins every `button` to `width: 124px` and a fixed height, so the label wrapped to a second line the panel then cut off. New shared `property-inspector/pi.css` (also de-duplicates the three panels' inline `<style>` blocks) sizes the button to its text, never wraps, and adds bottom padding so the last control is never flush against the panel's cut edge. Verified for all 9 translations: the widest label (pt_PT, 213 px) fits the 440 px panel
- Store zip rebuilt from the installed plugin folder

## 2.2.0 — 2026-08-11

- **Option Next now mirrors the highlight in the terminal** — pressing Next moves the TUI picker's highlighted row along with the deck screen (arrow-key injection via AppleScript, iTerm2 only), so the picker is usable without the big key. Probed empirically: Down/Up move the highlight, Enter selects; the picker has an "Other" free-text row below the options, so navigation never crosses it — forward = single Downs, deck wrap-around = a burst of Ups back to the top. Serialized flusher: deck updates instantly, terminal catches up in order; any failed send latches mirroring off for that ask and the deck falls back to local-only cycling (OK's absolute digit always selects the right option either way). New `sendKeyByTtyScript` (iTerm2 adapter, down/up/tab/shift-tab), `canSendKeys`/`sendKeysToTty` (actions)

## 2.1.1 — 2026-08-11

- **Fix: deck keys went dead when a session worked inside a subdirectory.** Hook events record the session's *live* shell cwd (follows every `cd`), but the plugin matched it by exact equality against the claude *process* cwd, which stays frozen at the launch dir — mismatch → tty lookup failed → OK/Next/Compact/Clear presses did nothing (reproduced on hardware). The hook now records its controlling tty (`own_tty()`: fd ttyname → `/dev/tty` → `ps -o tty=`; keeps the last known tty on detection failure), and the plugin targets sessions by that tty first — trusted only while a live claude still sits on it (tty names get reused) — with the old cwd match as fallback for old state files (`claudeTtyForSession`, `focusClaudeSession` in `plugin/actions.js`)
- Plugin debug logging: with the `.debug` marker present (same switch as the hook's `events.log`), plugin `log()` lines also append to `claude-state/.plugin.log` — Studio swallows plugin stdout, this was previously invisible. OK-press failure paths (no tty, write failed) now log their reason
